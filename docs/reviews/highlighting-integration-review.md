# Code-highlighting integration review

Reviewed the shared Shiki helper in `packages/ui/code/highlight.mjs`, its tests and CSS, the TypeShade inline-code remark plugin and Astro plugin order, and the TypeCV Marked renderer integration. This was an independent review of the current implementation; I made no source changes.

The helper escapes `&`, `<`, `>`, quotes, and apostrophes in token text and token styles. Shiki token contents are wrapped in selectable spans with both light and dark theme variables. Joining token lines with newline characters preserves the tested source text, and the focused block test confirms source text survives markup removal. The TypeShade plugin converts only qualifying inline-code nodes, skips headings so heading text and generated anchors stay stable, and runs after API links but before error/rule link plugins. Those later plugins skip raw HTML and existing links. Fenced `ts`, `typescript`, and `tsx` blocks are precomputed before TypeCV's synchronous Marked renderer runs, avoiding Promise output.

Language filtering leaves shell command prefixes, paths, WGSL attributes, `fn` declarations, WGSL `var<...>` declarations, common WGSL generic vector/matrix/array annotations, and selected WGSL built-ins unhighlighted. The detector is intentionally heuristic for language-less inline code; ambiguous function calls may still look TypeScript-like, but no concrete harmful match was found in the reviewed guide examples.

Verification evidence: `node --test packages/ui/code/highlight.test.mjs` passed during review, including name-vs-expression filtering, escaping, text preservation, light/dark variables, and fenced-code output. The actual TypeCV Marked pipeline test and generated-page test also passed: rendered pages contain token markup without `[object Promise]` and retain selectable code. The final canonical TypeCV Astro build and `test:links` passed all three tests. The earlier source-link assertion used output overwritten by a manual legacy build; rebuilding through the package script resolved it. Root browser smoke uses the installed workspace Playwright browser and passed for TypeCV and TypeNN. The production build entry point is now recorded in the TypeCV AGENTS.md.

No blocking defect was found in the reviewed implementation. Build-level TypeShade heading/link verification remains with the coordinated full-site build.
