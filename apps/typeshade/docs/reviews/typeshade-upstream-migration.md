# Upstream migration review

The TypeShade app now incorporates the site changes from upstream commits `ff8c807` and `3ac1d1f`, based on the clean upstream tree at `3ac1d1f`. The migration is app-scoped; repository-level deployment workflow and root README changes remain with the web repository owner.

The app advances its compiler submodule pin to `3e1e8420a5313e045beb175131148920bfdc2d07` (compiler source `a21f7024`). Because this app skips the intermediate web-app pin, the expected rule-history delta in `src/lib/examples.ts` reflects the full move from `91c2fe31` to `3e1e8420`: one added rule and eleven changed rules.

The migration brings in nullable value semantics and documentation, optional-value examples, compiler diagnostics, benchmark fixtures and catalogs, generated stills, and browser checks. Translation changes were reviewed alongside the English source and retained where they express the same feature behavior and limitations. Four conflict resolutions used upstream content only within the conflicting hunks; surrounding web-app editorial and template changes were preserved. The Korean rules guide drops the stale `8.24` explanation because the migrated source no longer documents that rule. The Korean CPU-oracle and values-and-mutation guides were updated to match the new source claims; their source hashes were refreshed against the pinned upstream guide text.

Repository links for public edit and documentation targets now point into `typeshade/web/apps/typeshade`. The compiler CLI's `--repo=typeshade.github.io` value remains unchanged because it is a compiler contract identifier. New site issues and the setup script now target `typeshade/web`; the existing GitHub App must be installed there with issue permissions before the production cutover. The compiler issues continue to target `typeshade/typeshade`. `history.json` keeps its immutable legacy boundary at web baseline `f1eb89c`; the upstream source history is not introduced as a merge parent by this migration.

The full package production build passed after the issue target change: Astro built 2,532 pages and Pagefind indexed 2,494 pages across English and Korean (44,691 words). It emitted the existing Astro Markdown deprecation, dual-compiler-instance advisory, Zod annotation and large-chunk warnings. Pagefind also skipped 114 fragment pages without an outer `<html>` element and noted that Korean stemming is unsupported; the overall build completed successfully. The nullable Playground check passed in English and Korean on WebGPU and WebGL2, including accepted source, the expected TypeShade diagnostic for invalid nullable use, and repair. In this managed environment, browser-localhost traffic is blocked by the configured proxy and direct browser access to the Monaco CDN is refused, so the check uses direct Chromium for loopback and Node's environment proxy for the CDN when `PLAYGROUND_MONACO_VIA_NODE=1` is set.

The existing copy, locale, guide, sample, API, API translation, reference note lint, regression catalog and benchmark catalog checks passed during the package build. `check:types` passed for the app and Worker. `bun test scripts/benchmarks.test.ts` passed all 17 tests and 349 assertions, including compiler workload corruption checks, record validation and retry behavior, quotas, D1 failures, paired analysis, calibration, projections and report labels.

The full `check:benchmarks` browser/Worker run did not complete: its Chromium/WebGPU phase was still active after nine minutes when the shared execution server dropped the session, and the process was terminated before it wrote the extended-run and layout artifacts. The local Wrangler process from that run was stopped. This leaves the complete benchmark-page regression and responsive-layout run unverified in this environment; the deterministic benchmark unit suite above passed.
